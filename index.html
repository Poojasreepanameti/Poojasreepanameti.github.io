AI Speech Analysis Application

A Streamlit app that turns spoken audio into transcripts, speech insights and personalized feedback using OpenAI Whisper, with a technical interview practice mode.

Full project details

Record or upload your speech and get instant feedback on filler words, speaking pace, pronunciation clarity and grammar. Track your improvement over time, or practice technical interview questions by answering out loud and getting corrected.

Key features

  • Record with the microphone or upload wav, mp3 or m4a audio
  • Word-level timestamps from Whisper
  • Filler words, speech rate (WPM), pronunciation score and grammar checking
  • Secure registration and login with salted password hashing
  • Progress charts across sessions
  • Interview practice: answer by voice and get a verdict, the correct answer and delivery feedback
  • Question bank you can expand with a CSV file

How it works

Audio goes to Whisper, which returns text with word timestamps and confidences. The pipeline calculates filler counts, speech rate, a pronunciation score and grammar issues, and rule-based feedback turns those into advice. Results are saved in SQLite for progress tracking.

What I built

  • A modular architecture with one file per responsibility: transcription, analysis, feedback, authentication, database and visualization
  • The analysis pipeline and the rule-based grammar checker
  • Authentication and session storage
  • The Streamlit interface and the interview practice workflow
Challenges and solutions
  • Whisper removes filler words, so I used prompt conditioning to make it keep them.
  • To check grammar without Java, I built a lightweight rule-based checker instead of depending on LanguageTool.
  • For pronunciation, I used Whisper’s word confidence as a clarity signal and was clear about its limits.

Chronic Disease Prediction System

A machine learning app that estimates a person’s risk for 10 chronic diseases from 11 health and lifestyle inputs.

Full project details

I built an end-to-end application on the CDC BRFSS 2022 health survey, which has about 445,000 respondents. Users enter details such as age, BMI, smoking status and general health in a Streamlit interface, and the app returns a risk percentage for each disease.

What I did

  • Cleaned and prepared real-world survey data with pandas and NumPy
  • Encoded text columns with LabelEncoder and scaled features with StandardScaler
  • Handled strong class imbalance with SMOTE, applied to training data only to avoid data leakage
  • Trained one logistic regression model per disease with scikit-learn
  • Built a PyTorch neural network version and compared it against the baseline
  • Built the Streamlit interface for input, prediction and results

Diseases covered

  • Heart attack
  • Angina
  • Stroke
  • Asthma
  • Skin cancer
  • COPD
  • Depression
  • Kidney disease
  • Arthritis
  • Diabetes

Data

CDC BRFSS 2022 survey, about 445,000 respondents, with 11 inputs per person.

Intelligent Document Q&A Chatbot using RAG

Upload PDFs or text files and ask questions in plain English. The chatbot answers from your documents.

Full project details

A Retrieval-Augmented Generation (RAG) app that finds the most relevant parts of your documents with semantic search and gives them to an open-source LLM, so answers are based on the document content. It runs fully locally with no API key.

Key features

  • Upload multiple PDF and TXT documents
  • Text extraction, chunking and embedding generation
  • Semantic similarity search with a FAISS vector store
  • Grounded answers from the retrieved context
  • Chat-style Streamlit interface with conversation history
  • A “context used” panel so answers can be checked
  • Open-source models, no API key

How it works

Text is split into chunks and embedded with a Hugging Face sentence-transformer model, then stored in a FAISS index. For each question, the app retrieves the three most similar chunks and passes them to Qwen2.5-0.5B-Instruct, which is instructed to answer only from that context.

Upload → extract text → chunk → embed → FAISS
Question → embed → top 3 chunks → prompt → LLM → answer
What I learned and challenges
  • Built a complete RAG pipeline and learned how chunk size, overlap and the number of chunks retrieved affect answer quality.
  • A newer transformers release removed the text2text-generation task, so I switched from flan-t5-base to a decoder-only instruct model (Qwen) using the text-generation task.
  • Used Streamlit session state and caching so models load once and the index persists across reruns.
Limitations and future work
  • Scanned PDFs are not supported because there is no OCR.
  • Each question is answered independently, so follow-up questions are not supported yet.
  • The index is kept in memory and not saved to disk.
  • Planned: a larger LLM, source page citations, saving the index and using chat history.
